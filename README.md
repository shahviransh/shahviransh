# Personal site

This repo also hosts the personal site (software developer and security analyst). It is a single-page [Nuxt 4](https://nuxt.com) app with a light and dark terminal-inspired theme. Pushing `main` publishes it to [https://shahviransh.github.io](https://shahviransh.github.io) (GitHub requires the published files to live in `shahviransh/shahviransh.github.io`).

## Stack

- [Nuxt 4](https://nuxt.com) (SSR, no pages router - the whole site is `app/app.vue`)
- [Tailwind CSS 4](https://tailwindcss.com) via `@tailwindcss/vite`, themed with CSS custom properties
- No UI or animation libraries; the motion is hand-rolled CSS plus a few small composables

## Layout

```
app/
├── app.vue                     # Section order and page shell
├── assets/css/main.css         # Theme tokens, utilities, keyframes
├── components/
│   ├── sections/               # One component per page section
│   └── *.vue                   # Navbar, footer, cards, terminal chrome, icons
├── composables/
│   ├── useActiveSection.ts     # Scroll spy for nav highlighting
│   ├── useTextScramble.ts      # Decrypt-style text cycling in the hero
│   └── useTheme.ts             # Light/dark toggle backed by localStorage
├── data/site.ts                # All copy: profile, experience, projects, skills, credentials
└── plugins/reveal.ts           # `v-reveal` scroll-reveal directive
```

Content edits almost always mean editing `app/data/site.ts` only.

## Theming

Colours are CSS custom properties on `:root` and `.dark`, mapped into Tailwind through `@theme inline`, so utilities like `bg-surface` and `text-muted` resolve per theme without any `dark:` variants in components. The stored theme is applied by an inline script in `nuxt.config.ts` before first paint to avoid a flash of the wrong theme.

## Accessibility and motion

- Every animation is gated behind `prefers-reduced-motion`.
- Scroll-reveal is scoped to `html.js`, so content is never hidden without JavaScript, and falls back to showing everything if `IntersectionObserver` reports nothing.

## Résumés

The two résumé PDFs in `public/` are pulled from the private `McMaster-University` repo (`Resume Software/` and `Resume Security/`) by [`.github/workflows/sync.yml`](.github/workflows/sync.yml). That workflow is dispatched when those PDFs change.

## Development

```bash
npm install
npm run dev      # http://localhost:3000
npm run generate # static build used by GitHub Pages
npm run preview
```

[`.github/workflows/deploy.yml`](.github/workflows/deploy.yml) builds the site and pushes it to `shahviransh/shahviransh.github.io`, which GitHub serves at `https://shahviransh.github.io`. That deploy uses the `RESUME` secret (a PAT that can write to `shahviransh.github.io`).
